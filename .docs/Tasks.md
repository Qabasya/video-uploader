# Tasks — переход с Телемоста на OBS

**Дата постановки:** 2026-07-30
**Тип:** смена источника записей. Изменение точечное — новый формат имени файла + сужение расширений; архитектура, пайплайн, контракты с S3 и fs-lms не трогаются.

## Контекст изменения

Занятия больше не записываются в Яндекс Телемосте. Теперь преподаватель пишет урок в **OBS Studio** локально на своём ПК и после занятия копирует файл на шару в папку своей группы — как и раньше (`\\dc.fs.loc\Shares$\Video\<Группа>`).

| Что | Было (Телемост) | Стало (OBS) |
|---|---|---|
| Имя файла | `Встреча_в_Телемосте_08_07_26_16_04_45_—_запись.webm` | `2026-07-30_15-04-14.mp4` |
| Блок даты | `ДД_ММ_ГГ_ЧЧ_ММ_СС` (2-значный год, разделитель `_`) | `ГГГГ-ММ-ДД_ЧЧ-ММ-СС` (4-значный год, разделители `-` и `_`) |
| Контейнер | `.webm` | `.mp4` |
| Появление на шаре | копирование | копирование (без изменений) |

Зафиксированные условия (уточнены у пользователя 2026-07-30):

- **Автоматическое разбиение записи на части в OBS выключено** — один файл = одно занятие. Контракт с плагином (`1 s3_key` = `1 занятие`) сохраняется, склейка частей не нужна.
- **OBS пишет локально**, на шару файл попадает копированием — текущая логика `STABILITY_MINUTES` покрывает ровно этот сценарий, менять её не нужно.
- **Формат сразу `.mp4`**, без промежуточного `.mkv` и авто-ремукса — можно сузить `ALLOWED_EXTENSIONS`.
- **Поддержка старого формата Телемоста не нужна** — необработанных записей на шаре не осталось, default-паттерн заменяется, а не расширяется альтернативой.

Что **не** меняется и трогать не нужно: пайплайн, реестр, ключи S3 (`key_builder`), манифест, REST-контракт с fs-lms, `groups.yaml`, EventBus и события, логирование и `event`-лейблы Loki, Grafana-панели.

## Задача 6. Эксплуатационная заметка (только документация, кода нет)

- [ ] В `.docs/basic_doc.md` (раздел эксплуатации) зафиксировать риск, которого не было с Телемостом: **имя файла OBS собирается из локальных часов ПК преподавателя**. Телемост проставлял время на своей стороне; теперь сбитые часы на ПК → неверный `recorded_at` → плагин не найдёт занятие по дате/времени и вернёт `matched: false` (это WARNING, не ошибка — видео зарегистрируется и останется на ручную привязку). Рекомендация: ПК преподавателей в домене синхронизируют время с DC автоматически — убедиться, что служба времени на них не отключена.

## Quality gate

Перед закрытием этапа должно проходить чисто:

```bash
uv run ruff format . && uv run ruff check . && uv run mypy video_uploader && uv run pytest
```

## Критерии приёмки

1. Файл `2026-07-30_15-04-14.mp4` в папке группы проходит весь пайплайн: `recorded_at = 2026-07-30T15:04:14+02:00`, ключ S3 вида `videos/kege-1/2026/07/2026-07-30_15-04_<sha8>.mp4`, content-type `video/mp4`. ✅ (покрыто тестами пайплайна)
2. Ни в коде, ни в `.env.example`/`VU.env`, ни в документации не осталось упоминаний Телемоста как текущего формата (grep: `Телемост`). `.webm` как допустимое расширение остаётся — это про контейнер, не про Телемост.
3. Тесты не потеряли покрытие: default-паттерн, кастомный паттерн, fallback на mtime, невалидная дата — все ветки на месте. ✅
